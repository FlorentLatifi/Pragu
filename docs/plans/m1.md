Assumes Florent full-time (~40 h/week) with Claude. Estimates are in focused working days. They include tests and docs for each item.

**Exit criteria (from the brief):** every shipped "error" rule has precision ≥ 0.90 on Pragu Bench, published; 20 screens scanned within the agreed budget.

## Owner-implements (Florent writes, Claude reviews)

Briefs and test checklists: `docs/plans/owner-tasks-rules.md` (tasks 1–3) and `docs/plans/owner-task-sarif.md` (task 4).

1. `target/size` platform tier (below 48 dp, Android guidance), one level below the WCAG tier: info for now (ADR-007). Small, and teaches dp versus CSS px.
2. `name/generic` rule: string heuristics, very testable.
3. `contrast/non-text` rule: reuses the colour math from `contrast/text`.
4. SARIF writer: a mapping exercise against the SARIF 2.1.0 spec. Brief and test checklist ready: `docs/plans/owner-task-sarif.md`.

## Risks

- **Bench labelling effort:** start with fixtures, where we know the truth, before labelling real apps.
- **Scaling truncation needs a font-scale change on the device:** `adb shell settings put system font_scale 2.0` changes device state, so it must always be restored afterwards.
